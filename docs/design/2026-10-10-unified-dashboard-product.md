## 需求与设计

<a id="P-001"></a>
### P-001 用户、目标和工作台

主用户是负责 CI 与工程效能的维护者。一期支持发现异常、分析等待和执行耗时、定位 PR/批次/任务、核对来源证据、导出当前分析结果。维护者应能先回答“哪些项目值得关注”，再回答“哪一次门禁发生了什么”。开发者追踪单个 PR 是同一查询流程的辅助场景。

一期页面保持只读：重新加载已发布快照、分析范围选择、列表定位、下钻、导出和打开来源链接。页面不负责重跑门禁、改 PR 状态、直接启动后台采集、配置平台凭证或修改流水线。

现状首页 `#ubs` 是九仓 UBS 总览，Triton 是另一页；主标题固定为宣传式文案，而页面任务通过副标题与面包屑表达。依据：[index.html](../../web/index.html) L38–42、[app.js](../../web/app.js) L49–51。

目标默认入口是工作台，保留旧 `#ubs` 的 UBS 项目入口。工作台按项目呈现当前范围、数据时间、采集状态、问题记录数及可解释的项目指标，避免把 UBS 的 PR 代表样本与 Triton 的批次样本混成一个全站 E2E P90。工作台的“关注数”按稳定批次身份计数，项目数据不可用时显示状态而不是 0。

工作台线框：

```text
┌监控中心─────────────────────────────────────────────────────────┐
│ 工作台      项目选择：全部项目           快照状态 · 重新加载快照 │
├固定任务导航────┬────────────────────────────────────────────────┤
│ 工作台         │ 工作台                                         │
│ 项目概览       │ 每日统一采集：计划 07:30 · 上次发布 …            │
│ 趋势与任务     │                                                │
│ PR 与批次      │ [UBS：9 仓]                  [Triton：1 仓]      │
│ 数据质量       │ 当前数据范围/时间依据         当前数据范围/依据 │
│ 数据与采集     │ 项目指标及样本数              项目指标及样本数  │
│ 指标说明       │ 任务结果/数据版本/新鲜度       三维状态          │
│                │ [进入项目] [关注记录]         [进入项目]       │
│                │                                                │

```

工作台支持按项目缩小展示范围；它不提供未经定义的全站目标分支过滤或跨项目统计样本池。点击项目卡进入该项目概览，点击关注记录进入对应批次详情并保留返回工作台的上下文。

<a id="P-002"></a>
### P-002 项目、仓库与能力导航

“项目”是一个可独立配置采集与指标规则的监控对象，可以包含多个仓库。UBS 是九仓项目，Triton-Ascend 是单仓项目。仓库标识包含来源实例及完整 owner/repository，不仅使用仓名尾段；显示名称与稳定身份分离。

现状侧栏按 UBS/Triton 两组写死；UBS“单仓效率”和“数据质量”链接都指向 `ubs-engine`，仓库下拉只覆盖 UBS。依据：[index.html](../../web/index.html) L39、L44；UBS 九仓配置见 [repositories.json](../../repositories.json)。

目标使用一个项目选择器和一套固定任务导航：工作台、项目概览、趋势与任务、PR 与批次、数据质量、数据与采集、指标说明。项目选择只出现一次；不再为每个新增社区复制一组顶级菜单。项目中的仓库选择支持“全部仓库”和单仓，单仓项目默认选中唯一仓库，省去重复选择。

二级内容依据能力声明显示。UBS 保留仓库对比、代表批次、x86/ARM/DT、请求事件等内容；Triton 保留 E2E/NPU 联动时间范围、A3/A5 重点任务、workflow/attempt 等内容。没有来源字段的操作不出现有效控件：例如 Triton 当前没有 PR 生命周期状态，不能用批次成功/失败推断“开启中/已合入/已关闭”。

| 固定入口 | 二级内容与任务 | 项目能力差异 |
|---|---|---|
| 项目概览 | 关键指标、覆盖率/证据边界、仓库对比、关注记录 | UBS 显示九仓对比；Triton 单仓不重复展示无意义对比表 |
| 趋势与任务 | E2E 趋势、任务耗时/排队、任务类型 | UBS 使用代表样本趋势和 x86/ARM/DT；Triton 使用批次散点和 NPU 排队 |
| PR 与批次 | 默认批次，可切换 PR；搜索、排序、分页、导出 | 可切换的粒度与可用列由项目声明；未知值明确表达 |
| 数据质量 | 缺失、近似、关联、排除记录及来源 | 保留项目专有问题原因，不强迫使用相同采集规则 |
| 数据与采集 | 计划、任务结果、当前数据版本、采集/发布时间 | 一个公共只读入口，按项目和仓库查看 |
| 指标说明 | 指标定义、样本单位、时间依据、资格、单位、版本 | 通用概念加项目规则，指标旁可直达 |

项目页共用框架：

```text
项目选择 [UBS ▼]       面包屑：项目监控 / UBS / PR 与批次
PR 与批次
范围：仓库 [全部/单仓]  目标分支 [master]  PR 创建时间 [起止]
数据：采集于 … · 数据窗口 … · 版本 … · 当前状态 …
任务页签：项目概览 | 趋势与任务 | PR 与批次 | 数据质量
主内容：由任务与项目能力共同决定
```

点击任务导航保持当前项目/仓库与适用范围。切项目恢复该项目上次范围和列表状态，首次进入使用项目默认值；不把另一个项目的分支、任务类型或不适用的筛选静默套用过来。代码仓链接指向当前对象；仓库组链接注明是组织目录参考链接。

未来验收：[AC-002](2026-10-10-unified-dashboard-architecture.md#AC-002)；技术映射：[T-002](2026-10-10-unified-dashboard-architecture.md#T-002)。

<a id="P-003"></a>
### P-003 分析范围、时间依据和可比性

页级分析范围决定项目 KPI、趋势与分析分母，界面固定显示仓库、目标分支、时间起止和“时间依据”。没有相应来源能力的筛选不伪造。页面同时显示已发布数据窗口，用户选区只能使用该快照内已采集数据；扩大页面选区不等于重新采集历史。

| 项目 | 当前统计对象和默认窗口 | 页面时间范围的含义 | 保留边界 |
|---|---|---|---|
| UBS | 最近 30 天创建、目标分支 master 的 PR | 按 PR 创建时间选择 PR；保留选中 PR 的全部已采集批次 | 每个 PR 最长有效 E2E 批次作为代表值；批次不因列表定位被丢弃 |
| Triton | 最近 72 小时的提交/手动重跑批次 | 按批次本次起点 `start_at` 选择批次，含起止边界 | 起点未知的记录不伪造时间，不进入时间窗趋势，但能在数据质量中查询 |

当前 UBS 趋势按 PR 创建日聚合，Triton 两图共享按 `start_at` 过滤的时间导航器。依据：[app.js](../../web/app.js) L25、[triton-core.js](../../web/triton-core.js) L12–20、[index.html](../../web/index.html) L59–60。现有 Triton 时间筛选不保留无有效起点的记录，目标数据质量清单需明确呈现此类记录和排除数量。

每日统一采集使用一个固定截止点，各项目保留自己的窗口长度与时间依据；“同轮采集”不表示两个项目统计窗口或样本单位相同。页面选区、采集窗口、采集时间、发布时间分别标注。

同项目、多仓比较必须使用一致的指标 profile、时间依据和范围；范围不一致或未满足纳入规则的仓库仍可见，附上排除原因，不混入汇总。UBS 跨仓继续直接汇聚 PR 代表样本，不平均仓库均值/P90。

跨项目默认展示并列项目指标与口径标签，不混算 UBS 代表值与 Triton 批次 P90。若未来引入跨项目排名，必须先声明可比较指标的样本单位、资格、时间依据、窗口和单位。P90 是分布分位值，不是 SLA；“耗时偏长”依据 P90 的标签也不能解释为违反 SLA。

未来验收：[AC-003](2026-10-10-unified-dashboard-architecture.md#AC-003)；技术映射：[T-003](2026-10-10-unified-dashboard-architecture.md#T-003)。

### P-004 分析集合、列表定位与高级样本筛选

现状有两套搜索语义：UBS 搜索 PR 编号、标题、作者或 SHA 后重新计算指标、趋势和覆盖率；Triton 搜索编号/标题只过滤列表与 CSV，分支×时间窗才是页级集合。依据：[core.js](../../web/core.js) L13、[app.js](../../web/app.js) L19–23、[triton-view.js](../../web/triton-view.js) L202–205、L679。

目标区分分析集合 S 与列表集合 L。S 来自项目、仓库、目标分支、项目时间规则及显式统计样本条件；KPI、趋势、关注阈值和样本数都以 S 为依据。L 是 S 对应的已采集记录经过“列表搜索”和列表局部筛选后的集合；列表定位不改变 S、P90 阈值或覆盖率。

| 控件 | 位置与名称 | 影响对象 | 重置规则 |
|---|---|---|---|
| 分析范围 | 页面标题下的固定范围条 | KPI、趋势、分析分母及列表基础范围 | “重置分析范围”恢复项目默认值 |
| 图表筛选 | 图表标题旁；标明“仅本图” | 对应图及图内统计，不改变页级阈值 | 每图“全部”恢复；不改其他图或列表 |
| 列表搜索 | 列表工具栏；名称“搜索当前记录” | 当前实体列表及对应记录导出，不改变 KPI | 清空输入恢复该范围全部记录，回第 1 页 |
| 高级统计样本筛选 | UBS 分析范围的显式展开入口 | 选择 PR 样本，改变 S 和分析分母 | 显示常驻条件、分母与“一键清除高级筛选” |

公共列表定位支持项目已经提供的编号、标题、作者、SHA、批次/任务标识等字段；搜索提示根据能力列出实际可检索字段，不对未提供字段承诺结果。空白忽略、大小写不敏感，不把用户输入解释为可执行代码。

UBS 原来按 PR 状态、完整性、重跑/推送请求及全文条件筛选统计样本的能力移入高级入口，避免能力丢失。激活后必须显示例如“高级样本筛选：开启中 + 有重跑请求；分析 PR 12/203”，并提供清除入口。用户只在列表找一个 PR 时，指标继续描述原 S。高级筛选只选 PR，不重新选代表批次，详情保留全部已采集批次。

列表导出使用 L；“导出分析汇总”使用 S。两者按钮、范围与条数必须区分。搜索触发重新排序与分页重置，但不修改分析范围；搜索失败或无匹配记录的空态不得显示“项目无数据”。

未来验收：[AC-004](2026-10-10-unified-dashboard-architecture.md#AC-004)；技术映射：[T-004](2026-10-10-unified-dashboard-architecture.md#T-004)。

<a id="P-005"></a>
### P-005 关注批次去重与历史结果

统一关注区以稳定批次 ID 为唯一身份。同一批次同时满足“失败”“耗时偏长”“执行中/等待”“证据缺口”等条件时只出现一行，附多个原因标签；分组计数不相加为总数。总数表示唯一批次数，各原因数量可重叠并明确说明。

现状 UBS 展示每个 PR 最长失败等待和最长代表 E2E；Triton 按慢/运行/失败分组，同一批次可以在多组出现，小样本时慢组显示最长前 5。依据：[app.js](../../web/app.js) L94–95、[triton-core.js](../../web/triton-core.js) L134–163。

目标保留来源事实与项目策略：UBS 历史失败等待可以独立于代表批次被关注；Triton 保留以 S 的有效完成样本决定 P90 偏长或小样本最长前 5 的规则。规则由分析集合决定，列表搜索只定位已确定的关注记录，不能改变策略、阈值、分母或原因标签。

关注线框：

```text
需要关注的批次  [唯一 8 批]  原因：[全部▼]  搜索当前记录 [      ]
仓库 / PR / 批次        等待或 E2E      原因标签           历史事实
ubs-engine / #… / #…    183.69 min      失败 · 偏长        后续有成功
triton-ascend / #… / …  14.00 min       失败 · 证据缺口    未观测后续成功
[打开批次详情]          [查看全部批次]  [导出当前关注 8 批]
```

已采集范围内更晚成功不抹去先前失败；历史失败和后续成功分别显示对应批次、时间、身份与来源链接。只在当前已采集证据明确存在后续成功时显示“快照内后续有成功”，其余显示“未观测到后续成功”或缺证据，不能声称平台上从未成功。重跑数量、历史失败与后续成功不自动推断偶现失败、开发者习惯或根因。

“查看全部批次”进入完整记录，不受关注策略的前 5、前 8 或原因分组限制。关注导出和完整列表导出分别明确各自范围；批次稳定 ID 不能因排序、重复分组、重新采集或同仓 PR 编号碰撞而改变。

未来验收：[AC-005](2026-10-10-unified-dashboard-architecture.md#AC-005)；技术映射：[T-005](2026-10-10-unified-dashboard-architecture.md#T-005)。

### P-006 PR 与批次记录列表、分页和排序

公共“PR 与批次”入口默认显示批次，可切换到 PR 粒度。切换粒度保留分析范围和可用列表搜索，重置分页并采用该粒度默认排序，界面显式标注“PR”或“批次”；不把同一 PR 的多个批次合成一个不明样本。

批次默认按本次起点从新到旧，未知起点排在已知值后并保留身份。PR 默认按创建时间从新到旧；UBS 可选代表 E2E 降序、批次数降序。每个粒度支持适用的时间、E2E/观测时长、结果、仓库等排序；相等值使用稳定身份作为最终次序，缺值始终位于已知值之后，真实 0 是有效值。

现状 UBS 每页 15 条、三种排序和任务排队/执行/总耗时切换；Triton 全量列表按批次起点倒序且没有分页。依据：[app.js](../../web/app.js) L4、L27、[index.html](../../web/index.html) L55、[triton-view.js](../../web/triton-view.js) L540–544。目标保留原有排序能力并统一分页控件，默认每页 15 条，可选 15/30/50，显示“1–15 / 66 批次”。更改范围、搜索、局部条件、排序或实体粒度回到第 1 页；返回详情恢复原页和滚动位置。

```text
PR 与批次       [批次 ●] [PR ○]
分析集合：…     列表结果：66 批次（涉及 38 PR）
搜索当前记录 [编号/标题/…]  结果 [全部▼]  排序 [本次起点↓▼]
[可用列/任务耗时类型]                         [导出当前记录 66 批]
仓库 | PR | 批次/SHA/触发 | 结果 | 起点 | E2E/观测 | 证据 | 资格
…
显示 1–15 / 66 批次   每页 [15▼]    [上一页] 1/5 [下一页]
```

PR 行中的 E2E 表达根据项目 profile：UBS 明示“代表批次”；Triton PR 视图仅在 profile 有明确 PR 汇总规则时显示聚合时长，否则显示批次数/最近批次并引导到批次列表，不能临时计算一个 PR 平均/P90。未知 PR 身份的批次仍保留，可用批次或运行身份访问。

点击 PR 身份进入 PR 详情，点击批次身份进入该批次详情；来源外链不同时触发行展开。行快捷点击与显式按钮走同一详情路径。批次结果筛选不伪装成 PR 生命周期筛选。

未来验收：[AC-006](2026-10-10-unified-dashboard-architecture.md#AC-006)；技术映射：[T-006](2026-10-10-unified-dashboard-architecture.md#T-006)。

<a id="P-007"></a>
### P-007 统一详情、用户流程和证据路径

详情使用同一信息层级：PR → 已采集批次 → 任务 → 来源证据。宽屏使用固定详情侧面板或可路由详情页，窄屏使用完整页面；同一实体由列表、关注区或图表进入时使用同一内容和地址。图表悬浮/键盘聚焦提供简短预览，点击/Enter/Space 固定预览并提供“打开完整详情”。

当前 UBS 使用 PR dialog，按请求事件分组并默认展开代表批次；Triton 使用批次行展开和散点固定卡片。依据：[app.js](../../web/app.js) L98–99、[triton-view.js](../../web/triton-view.js) L469–519。目标统一容器和操作，不抹去请求事件与 workflow/attempt 的不同证据结构。

```text
详情：项目 / 仓库 / PR #…                       [复制链接] [关闭]
PR 标题、作者、来源链接、已知生命周期（不支持则“未知/未采集”）
数据版本 … · 采集时间 … · 证据覆盖边界 …
批次选择：已采集 N 批 [本次选中 ●] [UBS 代表批次标记]
  批次身份 / SHA / 触发或 attempt / 原始与显示结果
  起点 → 结束或 as_of；近似来源；E2E / 已观测时长
  证据完整性与逐指标资格、排除原因
  任务同批时间线：等待 / 执行 / 总耗时 / 结果 / 原始任务链接
  来源证据：平台请求/运行/任务、关联依据、可访问的质量证据
[导出该 PR 全部已采集批次] [导出选中批次任务]
```

从批次行进入默认展开选中批次，从 UBS PR 行进入默认展开代表批次；无代表时显示原因并选择最近已采集批次，不伪造代表值。全部已采集批次可查看，包含请求未关联、关联失配、执行中与指标排除记录。UBS 未关联批次保留独立身份与 Jenkins 链接；Triton 初次提交与重跑 attempt 分开保留。当前已存在 attempt 历史补采，后续详情继续表达“已采集记录”与证据覆盖边界，不承诺恢复平台完整历史。

用户流程：

1. 日常巡检：工作台 → 发现项目关注数或延迟 → 项目概览 → 关注批次 → 任务时间线 → 平台原始任务/日志 → 返回原分析范围。
2. 找单个 PR：项目 → PR 与批次 → 列表搜索 → PR 详情 → 选中某次提交/重跑 → 核对任务与起点证据；搜索不改变页级 KPI。
3. 分析等待：趋势与任务 → 设置分析范围 → 图表局部选择失败/任务类型 → 查看图内样本数 → 打开对应批次 → 核对排队与执行；页级阈值仍来自 S。
4. 解释缺值：指标旁的样本数/质量链接 → 数据质量清单 → 缺失或排除原因 → 实体详情 → 来源证据或“证据不可访问/未采集”。
5. 导出复核：确认实体、S/L 条件、条数、单位与版本 → 导出 → 使用 CSV 身份与来源 URL 找回相同详情。

关闭详情返回发起列表/图表位置与焦点；后退/前进恢复详情与查询状态。来源证据没有公开链接时显示证据类型与状态，不提供失效链接，不把凭证或原始敏感响应加入公开页面。

<a id="P-008"></a>
### P-008 执行结果、证据完整性和指标资格

状态采用三个独立维度；公共组件不得由任一维度推导另两个维度。

| 维度 | 用户表达 | 规则 |
|---|---|---|
| 执行结果 | 成功、失败、取消、执行中、未知；必要时显示原始状态 | 反映平台执行事实；取消按实际标记表达，不默认改成失败或剔除 |
| 证据完整性 | 完整、部分、缺失、关联待核验；近似起点另附来源 | 成功可伴随证据缺口；运行中不是自动的数据质量失败 |
| 指标资格 | E2E/排队/执行/任务总耗时分别“纳入/排除/未知”及原因 | 由项目 profile 和该指标证据判定；一个指标不合格不自动删除其他指标 |

现状 UBS 的 `cancelled` 可以与 `status=failure`、有效 E2E 同时存在；代表值由 `eligible` 和合法时长选择。Triton 的完成样本由 success/failure 和有效时长决定，`missing` 另计证据缺口。依据：[core.js](../../web/core.js) L7–9、[app.js](../../web/app.js) L98、[triton-core.js](../../web/triton-core.js) L60–88。迁移适配器保存原始结果、取消标记与 profile 资格，公共显示取消时不得改变历史样本资格。

合法时长必须是有限、非负原始数值；缺失、不可解析、负值、NaN、无穷不转为 0。真实 0 纳入合法性判断。任务缺排队分项时排队和总耗时保持未知，已知执行耗时仍可用。同类任务关联不唯一时不从其他批次补值；排除记录仍可查看。

Triton 起点未知、起点近似、运行中观测、NPU 明细缺失分别表达，不用一个“失败”标签覆盖。运行中时长注明观测参照 as_of，不计作完整终态等待。UBS 代表资格与 Triton 完成资格分别由各自 profile 声明；不把“取消”设成公共的默认纳入/排除条件。

数据质量页能按问题类型定位实体，显示影响的指标、原因、证据状态和来源链接。无质量问题、无有效样本、无数据、数据读取失败是不同空态。Triton 无 PR 生命周期字段时显示“未采集”，隐藏对应有效筛选，不以执行结果生成“已合入/已关闭”。

### P-009 时长、精度、时间和视觉表达

列表、KPI、图表与时间线主单位统一为分钟，列名/轴标签明确标注 `min` 或“分钟”。主体保留两位小数，非零且不足 0.01 分钟显示“<0.01 min”，真实 0 显示“0.00 min”，未知显示“—”并附原因。详情和可访问的精确值提供秒/毫秒及原始单位；格式化不得修改计算输入。

当前 UBS 显示两位分钟并在悬浮查看秒/毫秒；Triton 显示四舍五入分钟或小时。依据：[app.js](../../web/app.js) L6–9、[triton-view.js](../../web/triton-view.js) L26–37。统一展示后保留原 CSV 单位，不能仅换列名。

| 值的性质 | 显示示例 | 说明 |
|---|---|---|
| 完整终态、真实 0 | `0.00 min` | 0 与未知区分 |
| 完整终态、非零小值 | `<0.01 min` | 详情可见精确原值 |
| 近似起点 | `14.00 min · 起点近似` | 可查看 workflow_created/attempt_start 等来源说明 |
| profile 判定为观测值，如 Triton 执行中/取消 | `已观测 8.20 min · 截至 …` | 不冒充终态时长；不把此规则强制套给 UBS 完整且合格的取消批次 |
| 未知/缺证据 | `— · 缺请求起点` | 不绘制成 0 点，不填补平均/P90 |
| 小样本 | `P90 14.00 min · n=1 · 样本不足` | 分位值自表达，仍非 SLA |

页面统一使用 Asia/Shanghai 展示，标题或范围处明示时区；详情时间使用带年份的日期与秒精度，URL/数据保留明确时区的机器时间。批次起点、结束、采集参照、采集时间和发布时间不能共用一个无说明的“更新时间”。

颜色、图标和文本共同表达状态，不能只靠红绿区分。取消显示规则在列表、图表、详情一致；失败、提醒、成功导出分别使用不同通知语义。当前已有共享令牌、按钮、面板和焦点样式，作为统一基础继续使用；依据：[style.css](../../web/style.css) L31–86、L153–196、L351–361、L496。项目特色体现为指标和内容，不复制独立配色体系。

### P-010 导出实体、范围、条数和版本

导出与当前可见记录共享查询结果和稳定身份；分页、折叠、默认展开、显示列不能缩减导出集合。按钮旁或导出确认摘要明确实体、分析范围、列表条件、条数、单位、数据版本与口径版本。

| 导出入口 | 集合 | 关键说明 |
|---|---|---|
| 项目/仓库分析汇总 | S | 样本单位、有效分母、仓库纳入/排除与原因，不是当前分页 |
| 当前 PR/批次列表 | L | 按当前粒度导出全部匹配实体；显示条数，搜索与局部条件可追溯 |
| 当前关注记录 | 去重后的关注集合经列表定位 | 标明关注策略和多个原因，与完整列表导出区分 |
| PR 详情全部已采集批次 | 当前 PR 的全部已采集批次 | 不受代表批次、展开/折叠或列表搜索影响 |
| 选中批次任务/质量记录 | 明示的选中实体集合 | 包含任务身份、来源、证据与逐指标资格 |

新统一导出附上项目/完整仓库/PR/批次/任务身份、时间依据、S/L 条件、snapshot/release 标识、采集时间、时长单位和 profile 版本，可用独立 metadata 文件或自说明字段表达。技术文档定义具体格式，不能向 CSV 顶部插入会破坏现有解析器的任意说明行。

现有仓库汇总、UBS PR/批次/质量及 Triton 16 字段 CSV 保留为兼容导出，保持列名、顺序、单位、值规则和安全转义。新字段通过新版本格式/附属元数据交付，不静默重写旧文件。现状共用 `Metrics.saveCsv`，本地调用 `/api/export` 保存，静态站点浏览器下载；依据：[core.js](../../web/core.js) L15–25、[app.js](../../web/app.js) L97–108、[triton-view.js](../../web/triton-view.js) L22–23、L580–603。

导出期间禁用该按钮并显示状态，失败显示具体原因且恢复按钮；成功给出文件名、条数及本地保存/浏览器下载结果。合法空集合可以导出表头和范围元数据，明确“0 条”；数据不可用/无有效详情身份时不导出伪空成功文件。CSV 继续转义公式前缀，空值不写为 0。

### P-011 URL、恢复、导航历史与旧链接

URL 保存项目、任务页面、仓库、目标分支、时间范围及依据、实体粒度、列表查询、局部条件、排序、分页、显式高级样本条件和选中详情身份。用户复制 URL 后可重建同一查询意图；数据版本变化导致无法逐字还原的部分明确说明，不把新数据误称为原快照。

当前 Router 只表示 UBS/Triton/method、UBS 仓库和 quality 子页，旧哈希已规范化，直接导航推进历史、规范化替换当前记录。依据：[router.js](../../web/router.js) L2–31、[app.js](../../web/app.js) L29、L124。目标保留该历史原则：项目/任务/仓库切换与详情打开形成可后退节点；连续输入和拖动期间替换临时状态，结束动作记录最终范围，不让每次键入或像素拖动占一条历史。具体序列由技术验收锁定。

| 旧入口 | 迁移后保留的意图 |
|---|---|
| `#ubs`、`#repositories` | UBS 全仓项目概览，不被新工作台截走 |
| `#ubs/repo/NAME`、`#repo/NAME` | 相同 UBS 仓库的概览及原入口上下文 |
| `#ubs/repo/NAME/quality`、`#repo/NAME/quality` | 相同仓库数据质量 |
| `#overview` | UBS ubs-engine 概览 |
| `#prs` | UBS ubs-engine 的 PR 记录意图，避免默认批次粒度破坏旧入口目的 |
| `#quality` | UBS ubs-engine 数据质量 |
| `#triton` | Triton 趋势与任务，保留原看板入口目的 |
| `#method`、`#repo/NAME/method` | 指标说明；已知项目上下文可携带，但正文无需等待快照加载 |

新地址示意，不是本轮已实现接口：

```text
#workbench
#projects/ubs/overview?repositories=all
#projects/ubs/records?repository=gitcode%3Aopeneuler%2Fubs-engine&entity=batches&q=248&sort=start-desc&page=1
#projects/triton/trends?branches=main&from=2026-10-07T23%3A30%3A00Z&to=2026-10-09T23%3A30%3A00Z
```

缺省参数使用项目默认值；非法参数规范化并提示被忽略的条件，未知项目/仓库保持明确的未找到状态或回到可选择项目的入口，不借用另一个仓库的数据。日期越过新快照可用窗时按技术规则裁剪/恢复并通知；选中批次不在新数据中时关闭或显示已不可用，保留身份提示。

详情和导出绑定其打开时的数据版本和实体，不能随全局 currentRepository 变化串仓。导航/重载时清理不属于当前上下文的浮层与详情引用，关闭后恢复发起位置/焦点。原 CSV、CLI 和站点哈希均纳入迁移兼容清单。

### P-012 每日统一采集、手动补采与只读页面

目标为每日北京时间 07:30 统一启动采集，对应 UTC cron `30 23 * * *`。每轮对所有 `enabled` 社区调用相应采集器，可并行；全轮结束后等待统一验证和发布。所有项目使用同一固定截止点，并按项目窗口规则采集。允许通过既有后台入口/CLI 手动补采，仍遵循同轮采集、验证和统一发布契约。

07:30 是计划启动时间，不是数据刷新完成保证；GitHub 平台延迟、网络、配额、项目耗时和验证均可能推迟发布。页面展示计划、最后成功采集与发布时间，延迟提醒基于统一计划及明确配置的宽限，不复用当前 Triton 每日四槽位作新的预期。

现状每日全量在 07:30 同采 UBS 和 Triton，Triton 另有 08/13/18/20 增量工作流。现状页面“重新加载快照”只 fetch 已生成 JSON。依据：[README.md](../../README.md) L204、L214–216、[app.js](../../web/app.js) L109–124、[pages.yml](../../.github/workflows/pages.yml)、[triton-refresh.yml](../../.github/workflows/triton-refresh.yml)。本文定义后续收敛为每日统一调度；本轮不改上述工作流。

页面主动作仍叫“重新加载快照”，提示“读取已发布数据，不能触发采集”。点击后读取当前发布版本及其引用文件；只在版本验证通过后更新屏幕。后台补采可以通过“查看采集任务”链接进入已知来源页面或按文档命令由有权限者执行，不能用一个看似刷新页面的按钮隐藏后台写操作。

数据与采集线框：

```text
数据与采集                           [重新加载快照] [查看采集任务]
计划：每日 07:30（Asia/Shanghai）     本轮截止点 … / run_id …
项目          本轮任务结果        使用数据/版本        数据时间与新鲜度
UBS           完成/部分/失败      fresh/fallback/…     采集 … 截止 …
Triton        完成/部分/失败      fresh/fallback/…     采集 … 截止 …
展开：各仓状态、验证结果、错误来源、最近成功发布、具体排除原因
说明：计划启动 ≠ 更新完成；页面重新加载 ≠ 后台采集
```

<a id="P-013"></a>
### P-013 任务结果、数据版本、数据时间与降级

对每个项目分别展示本轮任务结果、当前使用的数据版本/模式、数据时间/新鲜度三个维度。采集失败但页面仍可展示旧数据，不得把“可展示”标成“本轮采集成功”；本轮成功也不表示此前缺口全部补齐。统一发布后每个项目可能使用不同采集时间的数据，必须逐项目标注。

| 维度 | 必需信息 |
|---|---|
| 本轮任务结果 | run_id、代码基线、固定截止点、开始/结束、成功/部分/失败/未执行及原因 |
| 使用数据版本 | release/snapshot 身份、口径/结构版本、fresh/fallback/unavailable、验证状态 |
| 数据时间/新鲜度 | 实际 collected_at、window 起止及时间依据、published_at、计划与延迟表达 |

失败项目只可复用通过结构、归属和指纹验证的旧快照，并保留旧窗口、旧采集时间、旧数据版本。不得用本轮发布时间冒充旧数据采集时间。没有可信旧快照则该项目不可用，其他成功项目仍可在全轮结束后统一发布；全轮所有项目均失败时保留整站上一版，后台任务报告记录本轮失败，站点不冒充发布了新数据。可信回退的结构兼容、并发覆盖和发布门禁细节以技术文档为准。

现状两域读取已隔离，重载失败保留旧数据，并用 generation 防止较早请求覆盖较新请求；仓库失败与待采集有不同状态，但跨仓表未纳入仓库最后一列仅显示“—”。依据：[app.js](../../web/app.js) L30–32、L83–89、L96、L109–121。目标在每一仓都显示任务/数据状态、排除理由和实际采集时间，不能让失败仓被一个破折号掩盖。

异常状态规则：

| 情况 | 页面行为 | 统计与操作 |
|---|---|---|
| 首次加载中 | 共用加载态/骨架，保留入口与指标说明 | 不显示 0 作为已知数据 |
| 成功采集、真实零记录 | “当前数据窗口内 0 个 PR/批次” | 0 数量合法；时长无样本为“—”；可导出 0 条 |
| 范围内无记录 | 提示当前仓库/分支/时间条件，提供清除范围 | 不回退为全快照数据 |
| 搜索无匹配 | “当前范围无匹配记录”，提供清空搜索 | KPI 与 S 不变 |
| 有记录但无有效时长 | 数量与排除原因照常显示 | 时长无样本为“—”，图不绘制假 0 |
| 部分采集 | 常驻说明涉及项目/仓库与指标可能低估 | 按 profile 资格纳入可用值，缺值不补零 |
| 本轮失败、可信旧数据 | “本轮采集失败；展示 … 的旧快照” | 旧值可查，freshness 与失败结果分别显示 |
| 无可信旧数据 | 项目不可用及具体原因 | 不生成成功空数据；其他项目可用 |
| 页面重载失败 | 保留当前已验证显示，说明数据未更新 | 恢复重载按钮；不清空有效页面 |
| 结构/归属/指纹不一致 | 拒绝混版数据，保留最后有效显示 | 点名问题文件/项目，提供任务/说明链接 |
| 全轮失败 | 站点仍是上一版；任务报告说明本轮失败 | 不以发布新版本伪造成功 |
| 数据延迟 | “预期更新已延迟，当前显示最后成功结果” | 延迟是观察结论，不自动认定采集失败 |

任何模块的失败提示不覆盖其他项目有效结果。错误信息不包含凭证；错误与空态有可读文本、可用恢复动作和状态播报。

未来验收：[AC-013](2026-10-10-unified-dashboard-architecture.md#AC-013)；技术映射：[T-013](2026-10-10-unified-dashboard-architecture.md#T-013)。

<a id="P-014"></a>
### P-014 窄屏、键盘与可访问性

共用框架在 390px 手机、平板和桌面都能识别当前项目、任务、范围和数据状态。窄屏导航可使用抽屉或紧凑栏，但每个入口保留可见名称和当前高亮；项目选择不依赖只在悬浮显示的提示。顶栏允许换行，重新加载快照动作完整可点击，不与时间重叠，无整页横向溢出。

当前已有顶栏换行、文字按钮不收缩、≤800px 图标轨微标签、减少动态效果和焦点样式；Triton 时间导航器、批次展开与散点固定卡片有键盘路径。依据：[style.css](../../web/style.css) L84、L123–128、L539–592、[triton-view.js](../../web/triton-view.js) L364–379、L480–497、L555–569、L657–668。这些行为是迁移保留项，不能只用新外观取代。

| 组件 | 键盘与窄屏契约 |
|---|---|
| 项目/范围选择 | 原生或等价语义，Tab 可达、名称明确；已选与清除可读 |
| 记录列表 | 身份/展开是命名按钮或链接；Enter/Space 与点击一致；来源外链不触发展开 |
| 详情 | 标题与关闭可读，焦点进入和返回合理；窄屏全页；后退恢复原位置 |
| 趋势散点 | 可聚焦并报出项目/PR/批次身份；Enter/Space 固定；Esc 关闭并回原点 |
| 时间导航器 | 整体/起点/终点三个命名滑块，方向键与 Home/End；值、边界及时间描述同步 |
| 重绘/过滤 | 原焦点对象仍在则恢复同对象，否则回到相关搜索/范围控件，不留死焦点 |
| 长表与时间线 | 模块内横向滚动或响应式卡片；关键身份、结果、时长不能仅被隐藏 |
| 通知/加载 | 适当 status/aria-live；错误、空态与数量不是只靠颜色表达 |

图内筛选与列表搜索均可由键盘完成，搜索没有输入时显示完整范围；已折叠的链接不进入 Tab 序。只悬浮可见的信息也能通过键盘/详情获取。减少动态效果模式保留完整功能；图表自适应刻度减少标签但不改变数据映射、统计或固定详情内容。

### P-015 第三社区与后续项目接入

第三项目接入只增加配置、采集/数据适配器和确有需要的特色模块。公共路由、加载器、固定任务导航和主工作流不按社区名称新增分支。项目描述包括稳定项目与仓库身份、来源、enabled、采集器、窗口与时间依据、更新计划、指标 profile、展示能力、数据路径及证据策略。

公共能力覆盖项目健康、分析范围、批次/PR 记录、详情、质量、导出与采集状态。特色模块以声明方式注册：UBS 的平台请求/代表批次/x86/ARM/DT，Triton 的 workflow/attempt/NPU/A3/A5 都是现有例子。新项目只有不同来源和同类指标时复用公共视图；确有新业务指标才扩展模块与 profile，不把一种平台的数据字段强塞进所有项目。

接入流程：

1. 确认项目/完整仓库稳定身份、统计对象、窗口、来源授权与证据边界。
2. 配置采集器、metric/view profile 和 capabilities，先保持 disabled。
3. 用离线 fixture 验证合法零数据、单样本、缺值、运行中、取消、重跑/重复、未知 PR、来源异常及指纹不一致。
4. 验证公共工作台/范围/列表/详情/导出/异常状态和 URL；确认没有新增按该社区名称硬编码的主路由/加载器/主工作流分支。
5. 通过来源、统计、工件和部署验收后再 enabled，纳入同一每日采集轮次。

第三项目 fixture 属于后续实现验收，并非本轮已经创建或通过。现有最小 fixtures 和统计纯函数测试可作为验收方式参考；依据：[README.md](../../README.md) L96–102、[triton_fixtures.test.cjs](../../tests/triton_fixtures.test.cjs)、[multi_repo_frontend.test.cjs](../../tests/multi_repo_frontend.test.cjs)。未来接入同名仓库、不同源实例或不同 owner 时不碰撞，不借用 UBS/Triton 数据填空。

未来验收：[AC-015](2026-10-10-unified-dashboard-architecture.md#AC-015)；技术映射：[T-015](2026-10-10-unified-dashboard-architecture.md#T-015)。

### P-016 指标说明、迁移和验收边界

每个指标旁提供样本单位、有效样本数和说明入口，指标说明页无需等待数据读取。定义至少包含：指标名称/profile 版本、样本对象、时间依据、起止规则、完整终态与观测值规则、逐指标资格、单位、分位数算法、缺值/近似策略、跨仓聚合规则和来源证据。

| 保留的现有口径 | 目标说明 |
|---|---|
| UBS PR 代表批次 | 最长合格 E2E；并列按 trigger 编号降序、URL 稳定次序；x86/ARM/DT 来自同一代表批次，每类必须是关联有效、唯一的已结束任务，结果符合既有终态规则，不从其他批次补值 |
| UBS 跨仓统计 | 汇聚当前有效入选 PR 代表样本，保持窗口一致性、失败/过期排除与空仓可见 |
| Triton 批次身份 | 初次提交按真实 PR head SHA；手动重跑按 run/attempt 独立，已采集历史保留 |
| Triton 起点来源 | 优先触发事件；无法恢复时按已有规则用本次 attempt 开始/最早 workflow 创建并标近似；无本次证据留空 |
| 均值与分位数 | UBS 保留其代表样本资格，完整取消批次可按既有 profile 合格；Triton 终态分位数样本是 success/failure 且有限非负 duration，running/cancelled 保留 observed；P90 使用 PERCENTILE.INC 线性插值，0 与空值区分，P90 不代表 SLA |
| 项目特色任务 | 保留 x86/ARM/DT 与 NPU 最长排队、A3/A5、失败步骤和平台原始链接 |

基线依据：[index.html](../../web/index.html) L59–60、[core.js](../../web/core.js) L5–14、[triton-core.js](../../web/triton-core.js) L51–96、[triton/dashboard.py](../../triton/dashboard.py) 的 `build_batches` 与 attempt 历史补采。现有 [frontend.test.cjs](../../tests/frontend.test.cjs)、[experience.test.cjs](../../tests/experience.test.cjs)、[triton_core.test.cjs](../../tests/triton_core.test.cjs) 和审计脚本保护统计与证据语义。设计不重新宣称已修复的旧问题，也不把派生自洽当成来源准确。

迁移以保留语义和可回滚为顺序：

1. 冻结当前数据、口径、链接与导出基线，建立项目配置、稳定身份、运行上下文和独立工件接口；保持旧视图可用。
2. 建立统一调度的影子流程，只生成工件并与旧流程比较，不竞争正式部署。
3. 验证降级发布、冷/坏缓存恢复、公开指纹、防旧覆盖和回滚后，一次切换为每日全项目统一调度，停用旧独立定时/部署入口。
4. 迁移公共导航、范围、查询状态、URL、默认批次记录、关注去重、详情与导出；区分 S/L，把 UBS 原搜索移入显式高级样本入口，项目 profile 继续负责统计与特色内容。
5. 通过第三项目 fixture 验证扩展边界，再启用真实新项目；删除兼容层前单独确认消费者与迁移期。

旧链接、CSV、CLI、快照/证据字段、有效样本资格和既有更新失败保护分别纳入兼容清单。新统一 CSV 使用版本化格式；数据 schema/profile 变更明确升级，不能为了共享组件而重写历史统计。原统计分母改变只来自用户显式选择或经说明与版本化的新规则。
