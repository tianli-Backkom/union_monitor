# 统一看板审查整改与验收需求

版本：1.0；日期：2026-10-12；规格基线：`94f63eaf5fc764b7a4f8eb45e51c2cade4d4f384`。

依据[最新审查报告](../../audit/2026-10-11/report.md)、[产品设计](../design/2026-10-10-unified-dashboard-product.md)和[技术设计](../design/2026-10-10-unified-dashboard-architecture.md)，将问题、待完成能力和补证事项统一拆成 **38 项需求、76 个自动化用例、76 条验收条件**。用途为开发分派、测试编写、回归保护和逐项验收。本轮交付规格与文档检查，不执行业务改造。

## 1. 阅读与验收规则

- `UDR-xxx` 为本次统一需求编号；`UDR-xxx-TCxx` 为自动化用例；`UDR-xxx-ACxx` 为验收条件。不重编号或覆盖历史 [REQ-001～REQ-051](../../audit/2026-10-09/requirements.md)。`R01～R12` 对应最新报告的问题组；未编号的补证及目标差距用报告章节名称追踪。
- **回归保持**：对应基础缺陷已修复，后续修改必须保留；**部分具备**：已有模型或部分保护，完整目标未验收；**待实现**：目标能力尚未形成；**待补证**：证据不足，不能断言实际故障或已经正确。状态按上述代码基线记录，不代替当前线上运行结论。
- 用例覆盖的 **现有** 表示已有对应自动化保护；**待补充** 表示有相关测试模块但该用例还需扩展；**待新增** 表示需要新的自动化入口。相关 helper 测试不能代替真实页面、默认采集器或真实发布编排验收。文档校验通过不等于业务验收通过。
- 每条 AC 必须记录：输入版本及指纹、代码 SHA、测试入口/命令、预期值、实际值、结果、证据链接。结果限定为通过、失败、未验证或不适用；不适用必须说明没有适用对象。不可把未验证标为通过，也不以提交标题、测试文件存在或历史绿色报告推导验收通过。
- 单元/契约测试使用固定时钟与独立预期集合；集成测试从实际 CLI/默认 adapter/HTTP 边界执行；页面测试使用真实 Chromium。平台操作在专用测试分支、测试发布环境或受控 Git/Release/部署服务中执行，禁止为验收制造生产故障。
- 浮点对照允许绝对误差不超过 `1e-6` 秒，即 `1e-3` 毫秒；身份、计数、文件集合及字节指纹严格相等。不能只比较四舍五入后的页面文本。
- UBS 以 PR 创建时间选样，保留入选 PR 的全部已采集批次；Triton 以批次起点选样。分析集合 **S** 控制 KPI/趋势；列表集合 **L** 在 S 上定位记录。P90 使用 `(n−1)×0.9` 线性插值；样本粒度、资格、窗口、算法版本兼容才允许比较，禁止跨项目混算。
- 2026-10-11 的 **371 条观测、93 个合格批次**及 **887/885** 差异是专用审查输入，不是未来每日数量门槛；93 不是 PR 代表样本数，也不证明所有真实 PR 已关联。旧 2026-10-09 的 66 批次 fixture 不替代这份输入。

## 3. 数据准确性与完整性

## 7. 实施与验收顺序

1. 先持续保护已修复基础能力：资格/整批覆盖、路由/生命周期/读取、legacy 错误状态、PR 门禁与当前健康检查。
2. 补 PR 关联、来源覆盖/计数账本证据；先获得可追溯数据，不以降低未知比例或固定历史数量伪造完整性。
3. 完成公共契约及 fresh/fallback、完整束、持久 verified、并发排序、公开核验和真实恢复部署，在测试环境跑完整故障矩阵。
4. 两社区真实 shadow 对照通过后，一次切换单一生产入口；同变更更新旧工作流、日程/健康与运行说明。
5. 迁移固定任务、分析/高级筛选、公共记录/详情/导出和 URL，再用第三社区完整链路验收扩展能力。

每阶段以对应 AC 和证据判定，通过一阶段不推导其他阶段完成。本文为统一需求基准，不承诺外部平台永不失败、不承诺未保存的历史完整，也不要求重做审查已认可的配色主题。
